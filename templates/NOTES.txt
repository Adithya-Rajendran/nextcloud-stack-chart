NEXT STEPS
----------

1. Watch the rollout:

   kubectl -n {{ .Release.Namespace }} rollout status deploy/{{ include "nextcloud-stack.nextcloud.fullname" . }} --timeout=600s

2. Check end-to-end health (after Pod is Ready):

   kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "nextcloud-stack.nextcloud.fullname" . }} 8080:{{ .Values.nextcloud.service.port }}
   curl -s http://127.0.0.1:8080/status.php | grep installed

3. Expose Nextcloud:
{{- if .Values.ingress.enabled }}
   Ingress is enabled for host {{ .Values.ingress.host }}:
     kubectl -n {{ .Release.Namespace }} get ingress {{ include "nextcloud-stack.nextcloud.fullname" . }}
   Point DNS for {{ .Values.ingress.host }} at your ingress controller's address.
{{- else if .Values.gatewayApi.enabled }}
   A Gateway API HTTPRoute is enabled (parent Gateway: {{ .Values.gatewayApi.parentRef.name }}):
     kubectl -n {{ .Release.Namespace }} get httproute {{ include "nextcloud-stack.nextcloud.fullname" . }}
   Point DNS for {{ .Values.gatewayApi.hostnames }} at the Gateway's address.
{{- else if .Values.cloudflare.enabled }}
   The Cloudflare addon is enabled. In the Cloudflare dashboard, point the
   tunnel's Public Hostname at the Service:
     http://{{ include "nextcloud-stack.nextcloud.fullname" . }}.{{ .Release.Namespace }}.svc.cluster.local:{{ .Values.nextcloud.service.port }}
{{- else }}
   No exposure method is enabled — the Service is ClusterIP only. Reach it via
   the port-forward in step 2, or enable one of ingress / gatewayApi / cloudflare
   in your values and `helm upgrade`.
{{- end }}
{{- if and .Values.networkPolicy.enabled (not .Values.cloudflare.enabled) (not .Values.networkPolicy.nextcloudIngressFrom) (or .Values.ingress.enabled .Values.gatewayApi.enabled) }}

   ⚠  NetworkPolicy is ON but networkPolicy.nextcloudIngressFrom is empty and the
      Cloudflare addon is off. The Nextcloud Pod will REJECT traffic from your
      ingress controller / gateway. Add its namespace/pod selector to
      networkPolicy.nextcloudIngressFrom and `helm upgrade`.
{{- end }}

4. First login:

   Username: from Secret/{{ .Values.nextcloud.admin.existingSecret }} key `admin-user`
   Password: from Secret/{{ .Values.nextcloud.admin.existingSecret }} key `admin-password`

   Read them:
     kubectl -n {{ .Release.Namespace }} get secret {{ .Values.nextcloud.admin.existingSecret }} \
       -o jsonpath='{.data.admin-password}' | base64 -d

   Rotate the password from the web UI immediately. Then enable TOTP/WebAuthn.

--------------------------

{{- if eq (.Values.networkPolicy.flavor | default "cilium") "cilium" }}
- The rendered network policy is a CiliumNetworkPolicy (cilium.io/v2) and only

  networkPolicy.flavor=kubernetes for the standard-v1 rendering.
{{- else }}
- networkPolicy.flavor=kubernetes renders standard NetworkPolicy v1 with three
  approximations (see templates/networkpolicy-v1.yaml): no Cilium-gateway
  identity, "world" egress = everything outside RFC1918, and kubectl Jobs may
  egress TCP 443/6443 anywhere (apiserver approximation).
{{- if and .Values.gatewayApi.enabled (not .Values.networkPolicy.nextcloudIngressFrom) }}
  ⚠  gatewayApi is enabled but networkPolicy.nextcloudIngressFrom is empty. The
     v1 flavor cannot auto-allow a gateway proxy: add your gateway's pods to
     nextcloudIngressFrom, or — on a CILIUM Gateway — use flavor=cilium.
{{- end }}
{{- end }}
{{- else }}
- ⚠  networkPolicy.enabled is FALSE — there is no default-deny around these
  pods. PHP-FPM :9000, Postgres :5432 and Valkey :6379 are reachable from any
  pod in the cluster unless you bring your own policy.
{{- end }}
{{- if and .Values.valkey.enabled (not .Values.valkey.auth.enabled) }}
- ⚠  valkey.auth.enabled is FALSE — Valkey accepts UNAUTHENTICATED connections.
  protected-mode does not apply once the server explicitly binds 0.0.0.0, so
  anything that can reach the pod can read/write Nextcloud's cache, sessions
  and file locks. Re-enable auth (scripts/bootstrap-secrets.sh creates the
  Secret) unless network policy fully isolates the pod.
{{- end }}
